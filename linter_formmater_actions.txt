  • Linter de PrintScript (módulo linter, implementan LintRule.kt):
      • IdentifierNamingRule.kt: Verifica que los identificadores cumplan con camelCase o snake_case.

          • SpaceAroundOperatorRule.kt: Espacios alrededor de operadores.
          • SpaceBetweenTokensRule.kt: Espaciado entre tokens.
      • Opcionales:
          • AssignSpacingRule.kt: Espaciado alrededor de =.
          • SpaceBeforeColonRule.kt / NoSpaceBeforeColonRule.kt: Espacio antes de :.
          • SpaceAfterColonRule.kt / NoSpaceAfterColonRule.kt: Espacio después de :.

          • IndentationRule.kt: Indentación dentro de bloques condicionales.

      1. Falta trigger en pull_request: El workflow solo se dispara con push a main (ci-cd.yml:3-6). No valida Pull Requests antes de mergear a la rama principal.
      2. Incremento de versión deshabilitado: En el job get_version (ci-cd.yml:27-31), el incremento automático de versión semántica está comentado temporalmente
      (#version=$(echo $version ...)).
      3. Ocultamiento de logs: El comando ./gradlew build --continue > .git/test-output.log (ci-cd.yml:63) redirige la salida a un archivo en lugar de imprimirla en
      la consola del Action, lo que dificulta ver directamente en GitHub qué falló si hay un error de compilación o detekt.

  Se utiliza la carpeta .git/ porque es un directorio especial gestionado por Git que nunca forma parte del control de versiones ni de los commits, funcionando como
  un almacenamiento temporal de archivos temporales/logs sin necesidad de ensuciar el directorio de trabajo ni agregarlo al archivo .gitignore.
